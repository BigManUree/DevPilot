## 2026-11-16 20:57 打包 DevPilot.exe
产物：`apps/desktop/pack-out/win-unpacked/DevPilot.exe`（180MB，整包 394MB），已实测启动：4 进程、37100 health 200、工作台正常渲染（9 项目）。未签名（no signing info → SmartScreen 会提示）。
打包中发现并修复的两个阻塞问题：
1) **Electron 33 内置 Node 20.18 跑不动后端**：`undici@8`（backend 直接依赖，model.service 用）需要 Node 22 的 `zlib.createZstdDecompress`，Node 20 下 require 即崩（`Cannot read properties of undefined (reading 'bind')`）。修复：`scripts/prepare-backend.js` 改为随包携带系统 Node 22 运行时到 `resources-backend/node/node.exe`，并保留 better-sqlite3 的 **node ABI(127)**（删掉原来替换 Electron ABI 130 的逻辑）；`apps/desktop/src/backend-manager.ts` 新增 `bundledNodePath()`，打包态优先用 `resources/backend/node/node.exe`，找不到才回退 electron-as-node。
2) **打包用了旧 dist**：只跑 `electron-builder` 会跳过 `tsc`，asar 里是旧 `backend-manager.js`（不含 bundledNodePath）→ 仍走 Node20 → 崩。必须先 `npx tsc -p apps/desktop/tsconfig.json`（emit）再打包。`pnpm run pack` 里已含 build，直接用它没问题。
其他：electron-builder 覆盖同名输出目录时会因 `app.asar` 被占用失败（无进程也占用，疑似索引/Defender）→ 用 `-c.directories.output=<新目录>` 绕过；宿主 safe-delete shim 会拦 `rm -rf`，用 mv 或换目录名。
备份：`.rollback-20261115-qa/prepare-backend.js.before-node22`、`backend-manager.ts.before-node22`
遗留：`apps/desktop/release/`、`release-20261116/`（各 13M，被系统占用暂无法删除/改名），确认后手动删。
