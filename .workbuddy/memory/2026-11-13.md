
## 一键启动前后端（fitness-nutrition-agent 案例）
- 问题：导入后只启动了前端。根因两个：① 识别引擎 Python 只在根目录找入口（本项目入口在 app/main.py）→ 后端没被识别；② autostart 只启动 primaryService()（第一条服务记录）。
- project-analyzer.ts：Python 支持子目录入口（app/backend/src/server/api 下 main.py/app.py）+ fastapi 依赖 → uvicorn 命令（uv.lock 存在时加 uv run 前缀）；streamlit 依赖 + 入口扫描 → streamlit-ui 服务。pyproject 依赖解析改为逐行扫描（uvicorn[standard] 的 ] 会截断 [^\]]* 正则）。
- autostart.service.ts：拆 runSingle/runMulti。多服务项目按依赖顺序（基础设施→backend→app→frontend）逐个启动+修复；startService 抛异常改为进修复流程而不是中止整个 job；job 报告含每服务 ✓/✗。
- project.service.ts reanalyze：新识别到的服务自动补录入表（同名跳过）——已导入项目重新分析即可补上漏识别的服务，无需重新导入。
- 本机注意：8000 端口在 Windows 系统保留段（HTTP.sys/PID 4 占用，netsh excludedportrange 可查），fitness 后端改用 18000。
- 验证：fitness 项目一键启动 3 服务全绿（uvicorn 18000 / vite 8001 / streamlit 8501）；http://127.0.0.1:18000/ 返回「健身营养 Agent」页面且 /health 200（FastAPI 同源托管 dist，该地址即完整可用入口）。
