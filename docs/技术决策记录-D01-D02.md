## D-02 git push 策略细化（架构债 #8 闭环）

### 策略（Git Agent / git 模块执行推送时强制）

1. **白名单远程**：`remote.url` 必须命中用户在配置中心登记的远程（未登记的 remote 一律拒绝 push）。
2. **分支保护**：
   - `main`/`master`：push 前强制 ① 工作区干净（无未提交变更）② 本地领先远程 ≤20 commit（超限要求分批）③ 禁止 `--force`（永远）④ 禁止删除远程分支
   - 其他分支：允许 force，但落 `warn` 级审计
3. **推送前检查**：① 密钥扫描（`sk-[A-Za-z0-9]{8,}`、`AKIA[A-Z0-9]{16}`、PEM 头）命中即拒 ② `node_modules/`、`.env`、`credentials*` 不在提交中
4. **审批联动**：push 属 `git_operation.push` 权限类别，默认走审批中心（与现有 allowPush 开关叠加——双门保留）
5. **审计**：每次 push 落 `git.push` 审计（remote/branch/commits 数/结果），失败含 reason

### 实现位置与状态

- 策略落点：`apps/backend/src/git/git.service.ts`（现有 commit/push 命令包装层）
- **当前状态**：策略已定义并写入决策记录；git.service 的 push 代码路径尚需按上述 1-5 实装（列入下一批），本轮先固化决策
- 回滚：决策文档删除即回退（无代码变更）
