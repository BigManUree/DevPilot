# DevPilot 上线差距分析（对标 WorkBuddy 级商业桌面应用）

> 评估日期：2026-11-17
> 评估对象：`C:/Users/administer/WorkBuddy/DevPilot`（Electron + NestJS + SQLite 本地优先工作台）
> 评估口径：不比较功能数量，只比较「能不能作为一个正式商业产品发出去、装上去、用一年、出问题能救回来」
> 代码基线：后端 15,314 行 / 前端 4,817 行 / 桌面壳 527 行 / packages 584 行 / scripts 800 行（自有代码约 2.2 万行）；git 67 提交

## 零、一句话结论

**功能面已经达到"内部可用的完整产品"（20 页、37 表、154 路由、173 单测、24 验收全绿），
但产品形态仍是"一个能双击运行的解压目录"。距上线缺的不是功能，是 5 层产品外壳：**

| 层 | 现状 | 缺口性质 |
|---|---|---|
| 分发层 | 只有 `win-unpacked` 目录 + 自签 dev 证书 | **上线阻断**（用户装不上、装上了被 SmartScreen 拦） |
| 更新层 | 只做到"查版本 + 下载 + SHA256" | **上线阻断**（装完就无法安全迭代） |
| 云侧层 | 纯本地单用户，无账号、无同步、无模型网关 | **形态级分叉**（决定你是不是"WorkBuddy 那种产品"） |
| 可观测层 | 完全空白（无遥测/崩溃上报/远程诊断） | **上线阻断**（线上故障只能靠用户口述） |
| 工程层 | 无 CI、无 lint、98 项改动未提交、无 LICENSE/CHANGELOG | **上线阻断**（无法稳定出包、无法多人协作） |

生态层（插件市场、开发者体系）与商业化层（授权/订阅/企业版）是上线之后的第二、第三阶段，
不构成首发阻断，但决定天花板。

## 二、P0 · 上线阻断项（缺一项就不能对外发版）

### P0-1 安装包与代码签名

| 项 | 现状 | 证据 |
|---|---|---|
| 打包目标 | **只有 `dir`（解压目录），没有 NSIS 安装包、无卸载器、无开始菜单项、无开机自启选项** | `apps/desktop/package.json` → `build.win.target: dir` |
| 签名 | 只有 `certs/devpilot-dev.pfx` 自签开发证书，Windows 不认 | 同上 `pack:signed` 脚本 |
| 版本信息 | `0.1.0`，无 CHANGELOG、无发布号规则、无版权/公司信息 | `apps/desktop/package.json` |

上线要求：
1. `target: nsis`（+ `oneClick:false`、`allowToChangeInstallationDirectory`、`perMachine:false`、卸载保留用户数据开关）；
2. 正式代码签名证书（OV 需累积信誉，EV 可即时通过 SmartScreen）；
3. 关于页/安装器/文件属性三处版本号统一，从 `package.json` 单点注入。

工作量：**S**（配置层，半天内做完，签名采购是外部流程）

### P0-2 自动更新闭环（当前只走了一半）

| 已做 | 缺 |
|---|---|
| 清单拉取（5s 超时 + 10 分钟缓存） | 清单**无签名校验**，被劫持即可推任意包 |
| 下载到 `data/downloads/` | **替换 exe / 回滚 / 差分更新 / 灰度分批 / 强制升级**全缺 |
| SHA256 校验 | 无发布服务器、无版本归档、无"当前版本→目标版本"迁移脚本 |

证据：`apps/backend/src/system.controller.ts:60-93`；`docs/未完成工作清单.md` B4「exe 替换/回滚需完整发布流水线」。

上线要求：清单用 Ed25519 私钥签名、客户端内置公钥验签；更新走独立 updater 进程（运行中的主进程不能自替换）；
失败自动回滚到上一版本；按比例灰度（先 5% → 50% → 100%）。

工作量：**M**

### P0-3 崩溃与遥测

grep `telemetry|sentry|crash report` 在全部源码中 **0 命中**。当前线上出问题的唯一信息源是用户口述。

上线要求（最小集，别做大数据）：
1. 崩溃上报：主进程 `uncaughtException`/`unhandledRejection` + 渲染进程 `window.onerror` + 原生 crashpad，落本地环形缓冲后按需上传（默认关闭、首次启动明示授权、可一键关）；
2. 关键指标埋点：启动耗时（已有 `startup-trace.jsonl`，直接上报即可）、任务成功率、审批拒绝率、模型调用失败率；
3. 服务端极简：一个接收端点 + 按版本/OS 聚合的看板。

已有可复用的东西：`apps/desktop/src/startup-trace.ts`、`apps/backend/src/startup-trace.ts` 已经在写结构化 trace，
把它接上上报就是 30% 的工作量。

工作量：**M**

### P0-4 CI/CD 与工程基线

| 项 | 现状 |
|---|---|
| CI | **无**（无 `.github/`、无任何流水线配置） |
| lint / format | **无** eslint、prettier、husky、commit 规范 |
| 版本管理 | 最后提交 `5143d5c`（2026-11-13）；**98 项改动未提交**（59 改 / 35 新增 / 4 删） |
| 法务文件 | **无 LICENSE、无 CHANGELOG、无 CONTRIBUTING、无隐私政策** |
| 测试入口 | 173 单测 + 24 验收只能手敲命令，未进任何门禁 |

这是当前**最危险**的一项：四天的核心修复（CSRF、端口误杀、启动性能、打包软链缺陷）全部悬在工作区，
一次误操作就没了。

上线要求：CI 三档（PR：typecheck + lint + 单测；merge：+ 验收 24 + 隔离实例 QA；tag：打包 + 签名 + 出 release），
`main` 保护 + 强制 review，Release 自动生成 CHANGELOG。

工作量：**S–M**

## 三、P1 · 产品形态差距（决定"是不是 WorkBuddy 那种产品"）

这里是**战略分叉**，必须先定，否则下面所有工作都会返工：

### 分叉 A：纯本地桌面工具（保持现状架构）

只需补完 P0 五项的"轻量版"：NSIS + 签名 + 更新 + 崩溃上报 + CI，**不做账号和云**。
对标产品：Obsidian、TablePlus、Raycast 早期形态。首发成本最低，但天花板是"卖 license 的工具"。

### 分叉 B：本地优先 + 云端账号（WorkBuddy 形态）

在 A 之上再加下面五项，工作量是 A 的 2–3 倍：

| 项 | 现状 | 需要什么 |
|---|---|---|
| 账号体系 | 只有本机 token 守卫（`auth.ts`），**无用户概念、无登录、无设备管理** | 账号服务 + OAuth/邮箱登录 + 设备绑定 + 令牌刷新 + 登出踢设备 |
| 多云同步 | 无 | 项目档案/记忆/工作流定义的服务端存储 + 冲突合并（CRDT 或 last-write-wins + 版本向量）+ 端到端加密开关 |
| 模型网关 | 用户自备 Key（`deepseek/openai/...`），无额度概念 | 服务端代理 + 配额计量 + 计费 + 失败降级（客户端降级链已有，服务端要接上） |
| 团队协作 | 无 | 组织/成员/角色（RBAC）、共享项目、审批流归属人 |
| 多租户隔离与合规 | 无 | 数据分区、审计导出、删除请求（GDPR/PIPL）、隐私政策 |

**这一块是"上线应用"和"能跑的程序"之间真正的分界线**：一旦有账号，就必须有
注册转化、找回密码、封禁、退款、数据删除、等保/隐私合规——这些不是代码问题，是运营问题。

### P1-2 国际化

grep `i18n|locale` 在源码中 **0 命中**，全部文案硬编码中文。

如果只做中文市场，可以不做；但只要想出海或进企业采购流程，i18n 必须**在文案量还小的时候**引入
（现在 20 页、约 4800 行前端，越晚越贵）。

工作量：**M**（提取 + en 翻译 + 日期/数字/货币格式化 + RTL 预留）

### P1-3 帮助与增长面

| 缺 | 影响 |
|---|---|
| 无官网 / 下载页 / 文档站 | 用户拿到 exe 之后没有第二次接触点 |
| 无应用内引导（已有"首次启动引导 WF-01"，但只是配置向导，无功能教学） | 20 页工作台的新用户流失 |
| 无示例项目 / 模板库 | 首次体验是空工作台（现有的 `tests/fixtures/demo-project` 可直接产品化） |
| 无更新日志展示 | 用户感知不到迭代 |
| 无反馈入口（内置 issue 上报带日志附件） | 收不到真实需求 |

工作量：**M**

### P1-4 前端架构债

`apps/renderer/src/App.tsx` **2250 行单文件承载全部 20 个页面**，`pages/` 只有 2 个入口，无路由、无代码分割。

证据：`docs/reports/全方位测试报告-2026-11-15.md` C-06（已列为保留项）。

影响：功能迭代速度、按页懒加载（启动优化报告里已列为 backlog）、UI 自动化测试无法按页面写。
建议在**下一次大功能之前**做，用现有 24 项验收兜底。

工作量：**M**

## 六、建议执行顺序

**第 1 周（把地基钉死，全是 S 级）**
1. 提交那 98 项改动，打 tag `v0.1.0-internal`；
2. 加 eslint + prettier + husky + commitlint；
3. 建 CI（typecheck / 单测 / 隔离实例验收），`main` 保护；
4. 补 LICENSE、CHANGELOG、隐私政策草稿；
5. `target: nsis` + 版本单点注入 + 卸载保留数据。

**第 2–4 周（可发布的最小闭环）**
6. 崩溃上报 + 启动 trace 上报（默认关闭、明示授权）；
7. 更新：清单签名 + 独立 updater + 失败回滚 + 灰度；
8. 正式签名证书落地，跑通"下载→安装→升级→回滚"四步真机验证；
9. 示例项目模板 + 应用内 3 步引导 + 反馈入口。

**第 2 个月（形态决策后）**
10. 分叉 A：macOS 公证 + Linux 包（若定位跨平台工具）；
11. 分叉 B：账号服务 + 设备管理 + 云同步 + 模型网关配额（需要服务端团队/预算）；
12. i18n 抽取（按市场决定是否翻译）。

**第 3 个月起**
13. 前端路由化拆分（趁 20 页还没变 40 页）；
14. 插件市场（签名 + 远端源 + 版本解析）；
15. 授权/订阅 + 企业版（SSO/RBAC/审计导出）。
