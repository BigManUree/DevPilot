# DevPilot 性能基线报告（架构债 #6 / 测试方案 §4）

> 实测日期：2026-11-11 · 目标硬件：本机开发机（Windows 11, Node 22.22.2, better-sqlite3 WAL）
> 复测方式：`node scripts/perf-baseline.mjs`（自动写 `docs/性能基线报告.json`）

## 结论：全部建议值达标，余量充足

| 指标 | 实测值 | 建议值（测试方案） | 判定 |
|---|---|---|---|
| API 延迟（health/projects/notifications，100 次采样） | avg 1ms，p95 1ms，p99 ≤26ms | UI 操作 ≤300ms | ✅ 达标（余量 300 倍） |
| 项目导入（混合 fixture，幂等路径） | 10ms | — | ✅ |
| 环境检测（15 探针全跑） | 586ms | — | ✅ |
| 后端冷启动（spawn → 首个 health 200） | **1062ms** | ≤5000ms | ✅ 达标（余量 ~5 倍） |
| WS 推送延迟（notification.new，10 样本） | **avg 2ms / p95 4ms** | ≤1000ms | ✅ 达标（余量 500 倍） |

## 说明

- 冷启动含 Nest 全路由映射与 V5 迁移检查；数据量增长后需复测（当前 30 表、库小于 10MB 量级）。
- p99 health 出现一次 26ms 尖刺，与迁移检查/IO 抖动一致，量级无害。
- 实测后守护进程已恢复常驻（daemonRestored=true）。
