# 项目识别与配置体检优化

- 日期：2026-11-15
- 触发：`D:\develop\AIHOT-main` 启动后被打开成 `http://127.0.0.1:8600` 的**目录列表**；导入时也没有校验配置（API Key 填错的也能过）
- 回滚目录：`.rollback-20261115-qa/`

---

## 一、根因（两条，均有证据）

### 1. 服务识别：monorepo + compose 双重误判
- AIHOT 是 npm workspaces 单仓（`apps/api`、`apps/web`、`apps/worker`），**根 package.json 只有 `dev:web`/`dev:api`/`dev:worker`，没有 `dev/start/serve`**。
  旧分析器只认根脚本 → 放弃识别应用；随后从 `docker-compose.yml` 里按关键词猜到 `postgres`（实际服务键是 `db`），生成 `docker compose up -d postgres`（这个服务名根本不存在）。
- 启动失败后修复 Agent 给出 `python -m http.server 8600` 并落库 → 浏览器打开 8600 就是仓库根目录的文件列表。
  证据（修复前 DB 记录）：`project_services: postgres | database | python -m http.server 8600 | port 8600`。

### 2. 配置校验：只看格式，不做真实调用
- `environments/environment.service.ts:validateEnvValue` 对 `*_API_KEY` 只检查「长度 ≥ 4」，填 `abcd` 也通过；数据库只做 TCP 连通；导入流程完全不校验。
- 实测该项目的 `LLM_API_KEY` 是失效的（`HTTP 401 Authentication Fails`），旧逻辑无法发现。

### 3. 附带发现的真实兼容 Bug
- 前端 `react-router dev` 启动即退出，日志：
  `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] targets: apps/web/.react-router/types`
  → DevPilot spawn 项目服务时继承宿主（编辑器/Agent）注入的 `NODE_OPTIONS` shim，构建工具清理临时目录被拦。已修复。

## 三、实测（AIHOT-main 真实项目）

**识别**
```
aihot_api    | backend  | port=3001 | npm run dev -w @aihot/api    | depends_on=[db]
aihot_web    | frontend | port=3000 | npm run dev -w @aihot/web    | depends_on=[db]
aihot_worker | backend  | port=null | npm run dev -w @aihot/worker | depends_on=[db]
db           | database | port=null | docker compose up -d db
```
启动 web 后 `http://127.0.0.1:3000/` 返回真实应用页面（`<title>MyHOT…`），不再是目录列表。

**配置体检（overall=warn）**
| 项 | 结果 |
|---|---|
| .env 配置 | ok（17 键） |
| 必填配置项 | warn：缺 `TRUST_PROXY`、`BAIDU_PUSH_ENABLED` |
| 占位值 | ok |
| 密钥强度 | warn：`POSTGRES_PASSWORD` 长度 6 |
| 大模型 Key（deepseek-flash） | **fail：HTTP 401，Key 无效**（旧逻辑完全发现不了） |
| 数据库连接 | ok：`127.0.0.1:5432` 可连 |
| 端口 3000 / 3001 | ok：空闲 |
| 数据库初始化 | warn：有 `db:migrate` 脚本，首次启动前需执行 |
| Node 版本 | warn：项目要求 `>=24.22.1`，本机 `22.22.2` |
| Docker | warn：依赖 docker compose，本机无 docker 命令 |

**启动向导**：提交 `LLM_API_KEY=sk-invalid-...` → `201 {"ok":false,"invalid":[{"key":"LLM_API_KEY","reason":"大模型服务 拒绝了这个 Key（HTTP 401）…"}]}`，且 `.env` 未被改动。

**修复守卫**：`db` 启动失败后 Agent 提议 `npm run dev` → 被拒绝，步骤写明「服务类型是数据库，但提议的命令不是数据库服务端程序」。

**为什么页面最终仍是 503**：项目 API 日志显示 `PostgresError 42703`（字段不存在）——数据库**没跑迁移**（compose 的 `setup` 服务负责迁移，本机没 docker 时不会执行）。DevPilot 已把这一点列进「数据库初始化」体检项。执行一次即可：
```bash
cd D:/develop/AIHOT-main && npm run db:migrate
```
