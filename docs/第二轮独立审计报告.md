# DevPilot 第二轮独立质量审计报告（2026-11-13）

> 审计方式：以当前代码库为唯一依据，不信任《智能化升级实施报告》的完成结论。
> 全部关键结论均有真实执行证据（编号 E1-E12）。用户数据与迁移历史未改动；所有修改文件的原件备份于 `.audit-backup-20261113/`。

## 一、独立审计结论

上一轮报告 **主体可信，但有 4 处与实际不符或夸大**：

1. **S1（workspace 任意盘读取）只修了一半**：`workspace.controller.ts` 有项目包含校验（E1），但 **Agent 用的 fs.read 走权限网关，网关层没有任何路径限制**——Agent（LLM 驱动）可以读盘上任意文件；`fs.list`/`fs.search` 更是完全绕过网关直读文件系统。报告的"路径必须位于已注册项目内"仅对工作区 UI 成立。→ 已修复（见 D1/D2）。
2. **"批准后恢复"链路不存在**：审批 approve() 之后没有任何代码恢复 WaitingApproval 任务，前端也没有恢复按钮——批准后任务永久滞留。报告 §四的 E2E 实录应是手工重调了 /run。→ 已修复（D4）。
3. **runtime.stop 完全绕过权限网关**（副作用工具无审批无审计）。→ 已修复（D3）。
4. **分析器端口解析缺失**导致 E2E 实跑暴露三个真实缺陷（Spring Boot 端口漂移 8080、FastAPI 硬编码 8000 撞 Windows http.sys、无 package.json 的 node 服务漏识别/误分类）。→ 已修复（D6）。

其余声称的能力经实测成立：数据库 v17 迁移（含旧库升级+备份）、统一导入六来源、24 条诊断规则、审批双门、依赖安装白名单、运行档案、审计脱敏、22/22 官方验收（E10）。

## 六、剩余风险

1. 审批为类别级授权：批准一次 command.exec 后该主体 30 天内同类操作免审批（有 projectId 范围）。建议后续做参数级绑定。
2. `npm install` 允许任意包（供应链面仍在），L2 审批是唯一闸门。
3. LLM 修复链路会真实改写项目文件（有备份+回滚），复杂场景仍可能改错方向。
4. 本审计全部在 Windows 单机执行，POSIX 语义未真机验证。
